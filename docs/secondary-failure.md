# Secondary 강제 종료 실험

2026-10-22 정상 3노드 클러스터에서 보상 지급 중 Secondary 하나에 실제 SIGKILL을 전달했다. 기존 Primary 유지, 쓰기 영향, 멤버 수 변화, 정합성을 관측하고 종료 노드를 복귀시켰다. 단일 실행의 절차 검증이며 반복 성능 실험은 아니다.

## 조건과 실행

- 시작 상태: mysql-3 PRIMARY, mysql-1/2 SECONDARY, 모두 ONLINE
- 대상: DB에서 조회한 ONLINE Secondary 중 이름순 첫 노드인 mysql-1
- 요청: 4개 작업자, 1,600건, 건당 100포인트, 작업자별 요청 후 0.05초 간격
- 연결: 매 시도마다 Router 경유 새 연결
- 재시도 한도: 최대 40회, 시도 사이 0.5초 대기
- 최소 20개 COMMIT 응답을 확인하고, 주입 직전에 대상 역할과 기존 Primary를 재확인
- 장애 후 상태·데이터 검사, 자동 재가입, 3노드 GTID·지급 검사, Router 점검 쓰기 순으로 실행

```powershell
.\scripts\secondary_failure.ps1
```

Primary 실험과 관측·부하·로그 수집 절차를 공유한다. 내부적으로 `primary_failover.ps1 -Scenario secondary`를 실행하며 기존 Primary 실험의 기본 동작은 유지한다. Primary 실험은 종료 노드를 보존하지만 Secondary 시나리오는 검증 후 기존 재가입 스크립트로 노드를 복귀시킨다. PowerShell과 Docker Compose가 필요하며 Windows에서 실행 검증했다.

| 항목 | 결과 |
|---|---|
| 종료 대상 | mysql-1 SECONDARY, exit 137 |
| Primary 유지 | 모든 성공한 관측에서 mysql-3 PRIMARY 유지 |
| 멤버 변화 | mysql-1 비정상 상태 감지 후 ONLINE 2개 관측 |
| 장애 감지 관측 시간 | 8.108744초 |
| 종료 명령 확인 이후 첫 COMMIT 관측 | 주입 명령 시작부터 2.672880초 |
| 장애 이후 최대 연속 성공 응답 간격 | 1.853168초 |
| 클라이언트 오류 시도 / 재시도 | 0회 / 0회 |

| 상태 조회 오류 | 0회 |

클라이언트 오류가 없었다는 사실을 지연이나 일시적인 처리 공백이 없었다는 뜻으로 해석하지 않는다. 최대 성공 응답 간격과 요청 지연을 별도로 기록했다. 첫 COMMIT까지의 값은 종료 확인 이후 첫 성공 관측이며, 이 실험에서 쓰기 중단과 복구가 발생했다고 가정하는 RTO 값이 아니다.

생존한 mysql-2와 mysql-3 각각에서 manifest·응답 로그와 DB의 요청 ID·사용자·금액·잔액을 대조했다. 두 노드 모두 통과했고 저장한 기준 GTID 적용도 확인했다.

## 처리량과 지연 관측

지연은 각 요청의 최초 시도 기록부터 COMMIT 응답 기록까지다. 연결 수립, 트랜잭션 처리, 클라이언트 로그 기록 비용을 포함하고, 요청 후 대기 간격은 제외한다. 처리량은 구간 내 COMMIT 응답 수를 해당 구간의 경과 시간으로 나눈 값이다. p50/p95/p99는 nearest-rank 방식으로 집계했다.

| 지표 | 장애 전 | 종료 명령 확인 후 |
|---|---:|---:|
| 관측 구간 | 2.669045초 | 79.630956초 |
| 구간 내 성공 응답 | 64건 | 1,514건 |
| 성공 요청/초 | 23.98 | 19.01 |
| p50 지연 | 91.50ms | 74.01ms |
| p95 지연 | 129.71ms | 497.74ms |
| p99 지연 | 144.07ms | 1,425.41ms |
| 최대 지연 | 144.07ms | 2,225.50ms |

주입 명령 시작부터 종료 확인 사이의 22건은 이 비교 표의 양쪽 구간에서 제외했으며 전체 정합성 검증에는 포함했다. 장애 전 구간이 특히 짧고 표본 수가 다르며 별도 워밍업·반복·자원 통제를 수행하지 않았다. 따라서 관측된 처리량 감소와 p95 증가는 이번 실행의 사실로 기록하되 Secondary 장애 자체의 성능 영향이라고 단정하지 않는다. 단일 호스트의 Docker, fsync, 관측용 컨테이너 실행 비용도 함께 작용한다.

## 복귀와 종료 판정

실험 부하가 종료되고 생존 노드 검증을 통과한 뒤 mysql-1을 재시작했다. 로그에서 mysql-2를 소스로 하는 GTID 기반 증분 분산 복구를 확인했다. 약 29.311326초 후 ONLINE 3개를 관측했고 mysql-1은 읽기 전용 Secondary, mysql-3은 쓰기 가능한 Primary를 유지했다.

복귀 후 3개 노드 각각에서 기준 GTID 적용과 이 실험의 지급 1,600건·잔액을 다시 확인했다. 승인 거래 누락, 중복, 잔액 및 입력 불일치는 모두 0건이었다. Router 점검 쓰기와 3노드 반영도 통과했다. 기존 볼륨을 보존했고 수동 Primary 지정이나 강제 Quorum 복구는 사용하지 않았다.
