# 초기 설계

클라이언트는 Router의 6446 포트로 쓰기 연결을 생성합니다. AdminAPI는 mysql-1을 최초 시드로 사용하고 단일 Primary 클러스터를 만듭니다. 이후 Primary 역할은 고정하지 않습니다.

관리 직통 포트는 3307/3308/3309이며 호스트의 127.0.0.1에만 공개합니다. DB 간 통신은 Compose 네트워크를 사용합니다. 각 DB는 독립 named volume을 사용합니다. 컨테이너 자동 재시작을 끄므로 강제 종료 실험을 가리지 않습니다.

초기 관리자 root 원격 계정은 격리된 로컬 실습용입니다. Router bootstrap에도 관리자 계정을 사용합니다. 운영 전환 시 별도 클러스터 관리자 및 Router bootstrap 계정, TLS 인증, 시크릿 저장소와 권한 분리가 필요합니다. lab_app에는 초기 쓰기 점검 테이블의 SELECT/INSERT만 부여합니다.

초기화 재실행은 기존 메타데이터를 조회하고 없는 멤버만 추가합니다. 기존 클러스터 전체 중단이나 Quorum 상실은 자동 복구하지 않고 오류로 종료합니다. 초기 빈 노드는 증분 복구로 가입시킵니다. 필요한 binary log가 없거나 다른 GTID가 존재하면 가입이 실패하며, 자동으로 clone이나 데이터 삭제를 수행하지 않습니다. 이 프로젝트의 전용 볼륨만 사용합니다.

3개 컨테이너는 물리적으로 독립된 서버가 아닙니다. 단일 호스트, Docker 엔진, Router는 공통 장애 지점입니다. Router는 기존 세션이나 COMMIT 응답을 복구하지 않습니다. 보상 지급 클라이언트의 재접속과 같은 request_id 재시도는 Phase 2에서 구현합니다.
